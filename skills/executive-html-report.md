# 高管与董事会 HTML 汇报生成技能 (Executive HTML Report)

本技能用于将用户的文字大纲、业务数据或战略文档，转化为符合**董事会与 C-Level 高管审美标准**的独立 HTML 汇报文件。成品兼顾**会前 iPad/PC 预读、会中 4K 大屏演示、会后 PDF 归档**三大场景，并严格遵循 **100% 纯离线可用**的安全规范。

---

## 一、 核心设计哲学（受众心智）

面向董事会与高管的汇报，核心诉求是**时间极度稀缺、结果导向、关注风险与 ROI**。设计必须贯彻以下原则：

1. **结论先行（BLUF 原则）**：首屏必须用极简语言交代背景、现状以及需要拍板的决策项。
2. **克制的高级感（Quiet Luxury）**：追求杂志编辑级的留白、细腻的 `1px` 分割线与瑞士网格的严谨，绝不为了炫技牺牲阅读效率。
3. **渐进式披露（Progressive Disclosure）**：主界面仅呈现核心结论与关键图表；详细测算依据、明细数据、考核指标收纳于可点击展开的折叠面板中，应对高管现场追问。

---

## 二、 强制技术规范（铁律，不可违背）

生成的所有 HTML 文件必须严格满足以下技术要求：

1. **100% 纯离线单文件（绝对零外链）**：
   - **禁止**引入任何外部 CDN 资源（禁止引用 Tailwind CDN、Google Fonts、CDNJS、ECharts/Chart.js 外部链接等）。
   - 所有 CSS 样式、JavaScript 交互脚本、图标及数据图表必须完全内嵌在同一个 `.html` 文件中。
   - 如需插入图片或公司 Logo，必须以 Base64 Data URI 形式内嵌，确保在**纯内网或拔掉网线的会议室公共电脑**上 100% 正常打开。
2. **原生高质感字体栈**：
   - 正文无衬线体：`font-family: -apple-system, BlinkMacSystemFont, "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Segoe UI", Roboto, sans-serif;`
   - 标题衬线体（可选，用于增强杂志感）：`font-family: "Songti SC", "Noto Serif SC", "Source Han Serif SC", Georgia, "Times New Roman", serif;`
   - 关键数字必须启用等宽对齐：`font-variant-numeric: tabular-nums;`
3. **高清离线数据可视化**：
   - 所有图表（柱状图、折线图、环形图、进度条、风险矩阵）必须使用**原生内联 SVG 或原生 Canvas** 编写，支持 4K 大屏无损缩放，并附带轻量级鼠标悬停（Hover）或点击切换维度交互。
4. **大屏演示与翻页笔适配**：
   - 顶部提供「大屏演示 / 退出演示」按钮，点击可切换至宽屏全屏模式（调用 `requestFullscreen`）。
   - 演示模式下支持键盘 `←` / `→` 及 `PageUp` / `PageDown`（适配会议室无线翻页笔）按章节平滑跳转，并在右下角提供悬浮页码控制器（如 `01 / 06`）。
5. **一键导出归档级 PDF**：
   - 必须编写完整的 `@media print` 打印样式：隐藏导航栏、按钮与悬浮控制器；强制白底高对比度；设置 `break-inside: avoid` 防止卡片和图表跨页截断；**打印时自动展开所有折叠的明细面板**，确保董办归档信息完整。
6. **交互稳健性**：
   - 严禁使用原生 `alert()` 或 `confirm()`，所有状态反馈使用页面底部轻量级 Toast 提示条。
   - 所有 JS 逻辑需包裹在 IIFE 与 `try/catch` 中，防止单点异常导致页面交互失效。

## 三、 视觉风格预设（二选一，默认融合使用）

根据汇报主题自动匹配或由用户指定以下两种风格之一：

### 风格 A：顶级咨询 / 杂志编辑风（稳妥、庄重，默认首选）

- **参考美学**：SiteInspire + Fonts In Use / Typewolf（《经济学人》、顶级咨询年报质感）。
- **适用场景**：战略规划、合规与风控、组织架构调整、董事会年度复盘。
- **核心 Design Tokens**：
  - 页面底色：暖白 / 浅灰 `#F8F9FA`；卡片底色：纯白 `#FFFFFF`；极细边框：`1px solid #E2E8F0`。
  - 主文字色：深炭黑 `#111827`；次要文字：`#475569`；辅助说明：`#94A3B8`。
  - 品牌主色（克制使用 1~2 种）：深海蓝 `#0F2942` + 暗金点缀 `#A67C37`（或墨绿 `#0F4C3A`）。

### 风格 B：现代商业 Bento 网格风（前沿、时尚、模块化）

- **参考美学**：Land-book + Behance + Mobbin（现代商业 UI 与发布会质感）。
- **适用场景**：数字化转型、AI 赋能落地、新业务孵化、市场与经营增长专项。
- **核心 Design Tokens**：
  - 采用圆角细腻（`16px`–`24px`）、带有微弱层次阴影的 Bento Grid（便当盒模块化网格）。
  - 强化交互反馈：卡片悬停微浮起、Tab 标签平滑切换不同测算情景（如“保守 / 中性 / 乐观”）。

### 严格避坑清单（Anti-Patterns）

- **禁止**使用暗黑赛博朋克霓虹风、低对比度灰字（会议室明亮 LED 屏和投影仪上极难看清）。
- **禁止**使用重度 3D 动效、粒子背景或滚轮劫持（Scroll-hijacking），避免分散高层注意力及破坏 PDF 导出。

## 四、 黄金页面架构（内容骨架）

除用户另有要求外，所有汇报页面默认按以下**「交互式专题简报」**架构组织（若用户明确要求纯 10 分钟脱稿演讲，则精简每屏字数并强化全屏分页感）：

1. **顶部毛玻璃导航栏（Sticky Header）**：
   - 左侧：汇报主题标识；中间：章节快速锚点胶囊；右侧：「大屏演示」与「导出 PDF」按钮。
2. **第一屏：封面与前言摘要（Executive Preface）**：
   - 会议元信息标签（汇报对象、周期、密级）、杂志级主副标题。
   - **30 秒核心摘要卡片**：固定拆解为 3 列——① 背景与动因、② 核心抓手/方案、③ 本次会议需拍板/达成共识的事项。
3. **第二屏：核心指标看板（KPI Bento Cards）**：
   - 3~4 张大字号核心指标卡（如 ROI、预算达成率、核心目标值），配状态标签（绿/蓝/金/预警红），3 秒抓住全局。
4. **正文区：模块化深度拆解（2~3 个核心章节）**：
   - 灵活组合「双栏对比（现状 vs 目标）」、「可展开详情的工程/举措卡片」、「左时间轴 + 右交互 SVG 图表」等版式。
   - 图表区提供至少 1 组维度切换按钮（如“趋势视图 vs 结构视图”或“情景测算切换”）。
5. **收尾区：风险矩阵与高层研讨/决策清单（Action & Decision）**：
   - 采用深色主视觉区块（如深海蓝 `#0F2942` 容器配白字金标）形成视觉收束。
   - 列出 2~3 个需董事会拍板或务虚会研讨的议题卡片，**支持现场点击高亮（标记为“● 正在研讨”）**，辅助汇报人引导会议节奏。
6. **页脚声明**：汇报部门、版本号及内部机密提示。

## 五、 标准执行流程（Workflow）

当收到用户的汇报制作请求时，按以下步骤执行：

1. **信息提炼与架构映射**：
   - 快速识别用户的**汇报对象、核心主题、关键数字、行动计划、决策诉求**。
   - 若用户素材中缺少“前言摘要”或“决策清单”，主动基于上下文提炼补全，并标注 `[建议数据/待确认]` 供用户替换。
2. **风格与形态判定**：
   - 战略/合规/治理类默认选用**风格 A（顶级咨询编辑风）**；创新/数字化/增长类默认选用**风格 B（现代 Bento 网格风）**；两者可有机融合。
3. **单文件全量编码**：
   - 一次性输出完整、可直接运行的纯离线 `.html` 文件，不使用省略号或占位符。
   - 使用语义化 HTML5 标签与清晰注释的 CSS 变量（`:root`），方便用户后续一键替换企业 VI 主色。
4. **交付说明**：
   - 简要告知用户已内置的交互亮点，并提醒经办人：**“保存到桌面后用 Edge/Chrome 打开，按 F11 或点击右上角‘大屏演示’即可使用翻页笔汇报。”**

---

## 六、 交付前自检清单（Quality Checklist）

输出代码前必须逐项核验：

- [ ] **零外链检查**：全文无任何 `http://` 或 `https://` 外部样式表、字体或脚本引用？
- [ ] **大屏可读性**：正文与卡片字号清晰，背景与文字对比度高，无刺眼暗黑霓虹？
- [ ] **BLUF 结构**：首屏是否具备清晰的“前言与核心摘要”，收尾是否有“决策/研讨清单”？
- [ ] **交互完整**：顶部导航高亮联动、详情折叠展开、图表维度切换、大屏全屏+键盘翻页、研讨卡片高亮是否全部生效？
- [ ] **打印适配**：`@media print` 是否隐藏了冗余按钮并自动展开了折叠明细？
